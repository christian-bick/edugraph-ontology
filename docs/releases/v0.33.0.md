# Release v0.33.0

This release adds two Scope descriptors for mathematical models and broadens the
description of `SpatialNumbers` to include representations across multiple dimensions.
The ontology and client-library sources are the same as the previously published
`preview-0.32.0-pre.1.00409a39c911` snapshot, from commit
`00409a39c911fa79adb911bf6b724a9d34473588`; the release preparation adds this note only.

## Model Scopes

- `BarModel` describes numerical values, quantities, and arithmetic relationships
  represented by proportional bar or strip lengths relative to an identified unit
  or reference whole. It specializes `SpatialNumbers` and translates `OneDimensional`.
- `AreaModel` describes numerical values, quantities, and arithmetic relationships
  represented by two-dimensional region areas relative to an identified area unit
  or reference whole. It specializes `SpatialNumbers`, expands `BarModel` and
  `NumberArray`, and translates `TwoDimensional`.
- `SpatialNumbers` now describes positions or extents across one or more spatial
  dimensions, including number lines, proportional bars, and partitioned regions.
  Its existing specialization of `NumberRepresentation` is unchanged.

## Compatibility and adoption

No existing identifiers are removed or renamed. Public TypeScript and Python query
APIs are unchanged. Generated clients expose the two additional Scope identifiers
and their authored definitions and relations. Content annotations can use these
Scopes when the corresponding model is involved in the competency; a diagram alone
does not establish that involvement. Follow the existing
[content-evidence guidance](../content-evidence.md) and
[annotation guidance](../annotations-and-models.md).

Consumers adopting the stable release from the preview above receive the same
ontology assertions and client behavior. Consumers adopting from `v0.32.0` should
review the added model descriptors and the clarified `SpatialNumbers` description.
Publishing this ontology release does not claim completion of any consumer migration.

## Verification and release assets

The tag workflow runs version-resolution tests and the authoritative Docker build,
including ontology and documentation validation, generated-client tests, typing and
packaged-consumer checks. It also tests the installed Python distribution on Linux
with Python 3.11–3.14 and on Windows with Python 3.14 before publishing the release.
These are mechanical gates, not a claim of exhaustive semantic validation.

The eight stable release assets are the four authored Turtle sources, generated
RDF/XML, `edugraph-ts.tgz` with version `0.33.0`,
`edugraph_py-0.33.0-py3-none-any.whl`, and `edugraph_py-0.33.0.tar.gz`.
