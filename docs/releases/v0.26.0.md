# Release v0.26.0

Shared TypeScript library APIs for released data and caller-supplied ontology snapshots.
Includes the RDF-aware inverse-relation diagnostic fix.

## Changes

- Separate `edugraph-ts/core`, `edugraph-ts/rdf`, and `edugraph-ts/generated` entry points.
  Core algorithms do not load the parser, released dataset, filesystem, or Markdown.
- Read-only snapshot contexts provide full-IRI lookup, authored and derived relation access,
  traversal, label eligibility, and existing constraint deductions. Generated helpers delegate
  to the same core algorithms.
- RDF parsing preserves term kinds, language/datatype, document-scoped blank nodes, graph terms,
  and source identity. Parse failures are explicit and associated with their source.
- The shared validator covers schema contracts, primary-only assertions, one relation per
  family, structural cycles/ordering/child roles, and progression cycles. Assessments expose
  passed, failed, skipped, and error outcomes, with structured navigation references.
- O3a retains its stable identifiers but references only NamedNode entities. Literals and blank
  nodes remain explicit in diagnostics; literal objects never receive invalid reversal guidance.
- Original authoring references and linked supporting documents ship with the package.
  `RULES.md` describes their locations and intentional repository-only links.

## Compatibility

The four authored Turtle sources are unchanged from v0.25.1. This release introduces no new
ontology inference or descriptor/cardinality rule. Python remains a descriptor/relation client.

Existing root imports and findings-only validation remain available. Use the new assessment API
to distinguish a passed check from a skipped one. The root parser returns the legacy projection;
the RDF subpath returns rich RDF records. The package has explicit public subpaths; migrate
undocumented deep imports to those entry points.

Query results are sorted by full IRI, so consumers must not depend on earlier traversal insertion
order. Boolean eligibility throws for unknown runtime IRIs; use lookup or `inspectLabel` when
handling arbitrary identifiers. Returned relation views do not mutate the underlying context.

See the [public API and migration guide](https://github.com/christian-bick/edugraph-ontology/blob/v0.26.0/libraries/typescript/README.md#6-supplied-snapshots-and-portable-imports).
Downstream editor adoption still requires its own projection adapter and roundtrip tests.

## Validation and publication

The source and O3a correction passed the full local Docker gate and preview CI. The release gate
also builds both clients and verifies ontology/documentation rules, RDF and snapshot regressions,
public assessment/CLI behavior, and the npm artifact's exports, declarations, browser bundles,
rule-document links, and selected generated-adapter equivalence.

Performance/work-counter tests remain deferred as recorded in the
[implementation plan](https://github.com/christian-bick/edugraph-ontology/blob/v0.26.0/docs/plan/shared-typescript-library-implementation.md). Incremental validation
is optional and not implemented.

The release publishes four Turtle sources, combined RDF/XML, `edugraph-ts.tgz`, and Python wheel
and source distributions through the [release workflow](https://github.com/christian-bick/edugraph-ontology/blob/v0.26.0/.github/workflows/release.yml).
